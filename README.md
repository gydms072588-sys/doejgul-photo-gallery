# 됒굴포토 샘플 갤러리 v2

## 주요 기능

- 기존 디자인을 바탕으로 한 4열 × 3행 갤러리 (모바일 2열), 3페이지 × 12칸 = 총 36칸.
- 페이지 1/2/3의 상단 제목은 **각각 독립적**이며 관리자에서 바로 변경.
- 상단 개구리: **사장 PICK**, 하트: **확정 선택**. 선택한 사진에 각각 표시/해제 가능.
- **상단 개구리 아이콘을 4초 안에 연속 5회 클릭**하면 관리자 화면으로 진입. 개구리 탭 5번은 보안 장치가 아닙니다.
- 관리자에서 사진 등록/교체/제거, 설명, 스티커 적용 가능.
- 갤러리에서 사진 클릭 → 전체 보기 / 원본 100% 확대 / 이전·다음 이미지 / 50% 워터마크.
- 관리자에서 GitHub API를 통해 사진·설정 파일을 저장소에 커밋해서 게시 가능.

## 파일 구성

```text
index.html          갤러리+관리자 UI (HTML·CSS·JavaScript 내장)
gallery-data.json   타입 이름, 사진 경로, 스티커 상태 및 표시 설정
photos/01.jpg       기존 01번 테스트 이미지 (게시 전 교체 권장)
.nojekyll           GitHub Pages 설정
CODEX_PROMPT.md     Codex에 전달할 업데이트 지시문
```

**중요:** CSS와 JavaScript는 `index.html` 내부에 있으므로 따로 `style.css`나 `script.js`를 연결하지 않습니다. 사진과 설정을 불러오기 위해 `photos/`와 `gallery-data.json`은 함께 올리세요.

## 로컬 테스트

1. ZIP 파일 전체 압축 해제.
2. `index.html` 더블클릭해 브라우저에서 열기.
3. 오른쪽 위 개구리 스티커를 5번 연속 클릭 → 관리자 진입.
4. 타입 이름을 수정하고, 사진 번호를 눌러 파일을 업로드한 후 개구리/하트 체크박스를 켜서 미리보기.
5. '갤러리로'를 누르면 방문자 화면으로 돌아갑니다.

`file://`로 HTML을 열면 브라우저 보안 정책 때문에 `gallery-data.json`을 직접 읽지 못할 수 있습니다. 이때는 내장 기본 설정으로 갤러리를 띄웁니다. **GitHub Pages에서 배포된 상태에서는 `gallery-data.json`이 정상 로드됩니다.** 로컬 미리보기에서 바꾼 설정은 브라우저를 새로 고치면 초기화됩니다.

## GitHub Pages 배포

1. GitHub 저장소 루트에 `index.html`, `gallery-data.json`, `.nojekyll`, `photos/`를 업로드. **ZIP 파일 자체를 올리지 마세요.**
2. GitHub 저장소 `Settings → Pages → Deploy from a branch → main / (root)`에서 배포.
3. 사이트 접속. 1~3 숫자를 누르면 타입별 제목이 전환됩니다.
4. **Codex로 기존 저장소 업데이트 시** `CODEX_PROMPT.md`를 전달하고 *이전 사진 파일은 보존*하도록 지시하세요.

기존 `photos/02.jpg` ~ `photos/36.jpg`가 있으면 해당 번호에 자동 표시하도록 호환 처리했습니다. PNG·WEBP 등 다른 확장자는 `gallery-data.json`에서 `src` 값을 직접 지정하거나 관리자 업로드로 재등록할 수 있습니다.

## 관리자에서 GitHub 직접 게시하기 (선택)

GitHub Pages는 정적 호스팅이므로, 미리보기에서 바꾼 내용이 자동으로 서버에 저장되지는 않습니다. 이를 위해 관리 화면에 **GitHub REST Contents API 연동**을 포함했습니다.

1. GitHub 계정 → `Settings → Developer settings → Personal access tokens → Fine-grained tokens`에서 토큰 생성.
2. **Repository access: Only select repositories**로 사진 갤러리 저장소 하나만 선택.
3. **Repository permissions: Contents / Read and write** 설정. 다른 권한은 부여하지 마세요.
4. 갤러리 관리 화면에서 사용자명, 저장소명, 브랜치(`main`), 토큰을 입력.
5. **연결 확인** → **GitHub에 변경사항 게시**.
6. 새로운 이미지 파일을 `photos/NN.jpg/png/webp`로 올린 뒤 `gallery-data.json`을 수정해 커밋합니다. GitHub Pages 배포가 완료되면 공개 사이트에 반영됩니다.

**토큰 보안:** 토큰은 브라우저 입력란에서 사용되며 `localStorage`, `sessionStorage`, 소스코드 또는 저장소에 저장하지 않습니다. 그래도 공개 사이트에서 사용자가 직접 토큰을 입력하는 방식이므로 별도 백엔드 로그인보다 보안 수준이 낮습니다. PC 공유 환경에서는 사용 후 탭을 닫고, 짧은 만료 기간·최소 권한 토큰을 사용하세요. 관리자 5회 클릭은 비밀번호가 아니며 아무나 들어갈 수 있지만, 토큰 없이는 GitHub 저장소를 변경할 수 없습니다. 추후 운영 규모가 커지면 서버 인증/OAuth로 대체하는 것을 권장합니다.

**게시 주의:** 기존 사진이 모두 JPG인 경우처럼 동일 경로에 업로드하면 덮어씁니다. JPG에서 WEBP로 교체하면 예전 파일은 삭제하지 않고 갤러리 설정만 새 경로로 바꿉니다. 각 사진은 8MB 이하로 제한합니다. 이미지를 여러 장 올리다가 중간에 실패하면 성공한 파일은 저장소에 남을 수 있습니다. 이후 다시 **게시** 버튼을 눌러 남은 변경사항을 반영해 주세요.

## Codex를 활용한 게시 (토큰 미사용 대안)

- 관리자에서 제목과 스티커 설정을 수정하고 **설정 JSON 내보내기** 클릭.
- Codex에 `gallery-data.json`과 새 이미지 파일을 전달한 뒤 커밋 요청.
- 이 경우 **내보낸 JSON만으로 새 사진 파일이 GitHub에 생기지는 않습니다.** 새 사진 파일 역시 함께 업로드해야 합니다.

## 저작권

사진 확대 화면의 `#됒굴포토` 50% 워터마크는 CSS 겹치기 표시입니다. 사진 원본에 영구 합성되지는 않습니다. 공개용 이미지 자체에도 워터마크를 합성하고 웹용으로 크기를 줄이는 것을 권장합니다.

## 테스트 내용

Chromium 자동화 테스트에서 3개 타입 이동, 관리자 개구리 5회 진입, 타입 제목 변경, 사진 업로드 미리보기, 개구리·하트 스티커, 확대 화면 워터마크 불투명도 0.5를 확인했습니다. GitHub 게시 절차는 실제 개인 저장소를 수정하지 않고 REST 요청 모킹으로 검증했습니다.
