# 됒굴포토 · 촬영 샘플 선택표 v3.1

의뢰자가 촬영 스타일과 구도를 선택하고 PNG 선택표를 사진사에게 전달하는 정적 갤러리입니다.

- 공개 사이트: https://gydms072588-sys.github.io/doejgul-photo-gallery/
- GitHub: https://github.com/gydms072588-sys/doejgul-photo-gallery

## 방문자 사용 방법

1. 하단 왼쪽 **타입 바로가기**로 촬영 타입을 선택합니다. 관리자가 지정한 순서로 표시되며 모바일에서는 전체 너비로 표시됩니다. 타입 변경 시 해당 타입의 샘플 1페이지로 이동합니다.
2. 한 번 클릭하면 확대됩니다. 원본 100% / 화면 맞춤, 이전·다음, ESC 닫기를 지원합니다.
3. 두 번 클릭하거나 모바일에서 빠르게 두 번 탭하면 빨간 하트로 선택됩니다. 다시 두 번 누르면 해제됩니다. 사장 PICK인 개구리 샘플은 확대만 가능합니다.
4. 상단 요약에서 선택 개수·타입·샘플 번호를 확인하고 **♥ 사진 추가**에서 개별 또는 전체 해제합니다. 하단 가운데 **〈 샘플 1 / 2 〉**는 현재 타입 안의 샘플 페이지를 이동합니다. PC 4열·모바일 2열이며 한 페이지 최대 12개입니다. 타입 이동과 샘플 페이지 이동은 별개이고, 이동해도 선택을 유지합니다.
5. **↓ 선택표 저장**으로 `됒굴포토_샘플선택표_YYYYMMDD.png`를 저장해 사진사에게 전달합니다. 타입 이름, 타입별 샘플 번호, 하트, 50% 워터마크를 포함하며 사진 비율을 유지합니다.

방문자 선택 ID와 온보딩 닫힘 상태만 해당 사이트의 localStorage에 저장합니다. 다른 방문자와 공유하지 않으며 GitHub 게시 데이터에 포함하지 않습니다. 브라우저 저장소를 사용할 수 없으면 현재 탭에서만 유지됩니다.

## 관리자 사용 방법

1. 상단 **개구리 아이콘을 4초 안에 5회 클릭**합니다. 사진 위 개구리 스티커에서는 진입하지 않습니다.
2. 타입 이름을 수정하거나 **새 타입 추가**를 누릅니다. 고유 ID와 샘플 슬롯 12개를 생성합니다. ↑/↓로 순서를 바꿔도 ID·사진 경로는 유지됩니다.
3. 타입 삭제 전 등록된 사진 수를 확인하고 팝업에서 승인합니다. 최소 하나의 타입은 남겨야 합니다. 타입·사진 삭제는 목록에서만 제거하며 저장소의 원본 파일은 보존합니다.
4. 타입과 슬롯을 선택하여 JPG/PNG/WEBP(8MB 이하)를 등록·교체하고 설명과 사장 PICK을 편집합니다. 실제 이미지로 읽을 수 있는 파일만 받습니다. 사장 PICK으로 지정하면 현재 브라우저의 방문자 선택에서 자동 해제됩니다.
5. 편집은 즉시 미리보기에 반영되며 **GitHub에 게시**해야 공개됩니다. 게시되지 않은 변경이 있으면 페이지 이탈 시 브라우저 경고를 요청합니다.

### 가변 샘플 타일

- **02 / 샘플 관리 → + 샘플 타일 추가**로 현재 타입의 끝에 빈 타일을 추가합니다. 새 타입은 이전처럼 12칸으로 시작하지만 같은 타입에 13개, 25개 이상 계속 추가할 수 있습니다.
- 현재 타입명과 **등록 샘플 N개 · 사용자 페이지 M쪽**을 표시합니다. N은 빈 슬롯을 포함한 타일 수이며 M은 `max(1, ceil(N/12))`입니다. 12개는 1쪽, 13·24개는 2쪽, 25개는 3쪽입니다.
- 관리자에서는 모든 타일을 연속 그리드로 편집합니다. 새 타일도 사진·설명·사장 PICK·중복 검사·GitHub 게시를 동일하게 지원합니다.
- **사진 제거 · 타일 유지**는 빈 타일을 남깁니다. **샘플 타일 삭제**는 확인 후 타일을 제거하고 이후 표시 번호만 다시 매깁니다. 다른 샘플의 ID·사진·사장 PICK은 그대로 유지하며, 삭제된 샘플의 방문자 선택만 제거합니다. 원본 파일은 삭제하지 않습니다.
- 마지막 타일을 삭제한 타입도 유지됩니다. 새 타일 추가 또는 여러 장 업로드로 다시 채울 수 있고, 사용자 페이지 수는 최소 1쪽입니다.

### 사진 12장 일괄 업로드와 중복 안내

- 관리자 **02 / 샘플 관리**에서 편집할 타입을 고른 뒤 일괄 업로드 입력란으로 폴더의 사진을 한 번에 최대 12장 선택합니다. PC에서는 Ctrl 또는 Shift로 여러 파일을 선택합니다. 여러 번 업로드해 한 타입에 12장을 넘게 등록할 수 있습니다.
- 기본 **빈 칸에 추가**는 기존 사진을 유지하고 파일명 순서대로 빈 슬롯을 채웁니다. 공간이 부족하면 같은 타입 끝에 타일을 자동 추가합니다. 중복·오류 파일 때문에 빈 타일이 추가되지는 않습니다.
- **01번부터 순서대로 교체**는 확인 팝업 승인 후 교체합니다. 중복·오류 파일은 건너뛰며 나머지 슬롯과 저장소 원본 파일은 유지합니다.
- 파일 내용을 SHA-256으로 비교하여 다른 이름의 같은 사진, 같은 선택 묶음 안의 복사본, 다른 타입에 이미 등록한 사진에 **이미 올린 사진입니다**와 등록 위치를 표시합니다. 단일 사진 업로드에도 같은 검사를 적용합니다. 크기 조정·재인코딩된 사진은 별도 파일로 취급합니다.
- `photo-hashes.json`은 기존 이미지의 내용 해시 목록입니다. 새 사진의 해시는 관리자 게시 시 사진 설정의 `sha256`에 함께 저장하므로 새로고침 후에도 비교합니다. 기존 사진의 해시를 알 수 없으면 원본을 비교하며, 불러올 수 없는 사진은 비교 제외 수를 표시합니다.
- 슬롯의 **등록됨 / 게시 전 / 빈 칸**으로 현재 상태를 확인합니다. 공개 사이트 반영은 **GitHub에 게시**를 눌러야 완료됩니다.

### GitHub 게시 방법

- 계정 `gydms072588-sys`, 저장소 `doejgul-photo-gallery`, 브랜치 `main`을 사용합니다. Pages에서는 주소로 자동 입력합니다.
- 사용자가 발급한 Fine-grained PAT를 비밀번호 입력란에 입력합니다. 해당 저장소 하나의 **Contents: Read and write** 권한이 필요합니다.
- 토큰은 요청 때만 사용하고 코드·JSON·localStorage·sessionStorage에 저장하지 않습니다. 게시 성공 또는 갤러리로 돌아갈 때 입력란을 지웁니다.
- 개구리 5회 클릭은 인증이 아닙니다. 저장소 쓰기는 GitHub의 토큰 인증과 권한 검사를 거칩니다.
- 게시 전에 공개 설정과 원격 설정을 비교합니다. 다른 곳에서 변경했다면 덮어쓰지 않고 중단합니다. 편집 내용을 JSON으로 내보내 보관한 뒤 새로고침해 다시 편집하세요.
- 새 이미지는 기존 파일을 덮어쓰지 않는 고유 경로로 먼저 업로드하고 마지막에 `gallery-data.json`을 저장합니다. 일부 업로드 후 실패하면 현재 탭을 유지한 채 재시도하세요. 업로드에 성공한 이미지는 재전송하지 않습니다.
- 401·403·404·409 등 실패 상태를 표시하며, 실패해도 현재 탭의 편집 내용을 유지합니다. 사진만 올라가고 설정 저장에 실패하면 방문자 설정은 이전 상태를 유지합니다.
- JSON 내보내기는 새 사진 파일을 포함하지 않습니다. 이미지도 함께 게시해야 합니다.

## 파일과 기존 데이터 보존

- `index.html`: HTML·CSS·JavaScript·Canvas PNG 생성을 내장합니다. 외부 라이브러리나 빌드가 필요하지 않습니다.
- `gallery-data.json`: 기존 `schemaVersion: 3`과 `types[].photos[]` 구조를 유지하며 사진 배열의 12개 고정 제한만 해제했습니다. 기존 6개 타입·등록 사진 65장·설정 JSON을 이번 업데이트에서 변경하거나 초기화하지 않습니다. 별도 데이터 마이그레이션은 필요하지 않습니다.
- 타입·샘플은 전역에서 유일한 고유 ID를 사용합니다. 표시 번호나 타입 순서로 방문자 선택을 식별하지 않습니다. 기존 `doejgul.selection.v3`의 샘플 ID를 그대로 사용하므로 선택 데이터를 새 키로 옮기지 않으며, 삭제된 ID와 비정상적인 오래된 저장값은 정리합니다.
- 기존 `typeNames`, `photos`와 사진별 `confirmed` 등 v2 값은 마이그레이션 자료로 보존합니다. 관리자 확정 표시를 방문자의 개인 선택으로 전환하지 않습니다. v3 화면과 편집은 `types[]`를 사용하며 `typeNames`는 게시할 때 갱신합니다.
- 기존 `photos/01.jpg`와 등록 사진 메타데이터를 그대로 보존했습니다. 기존 13번은 두 번째 타입의 샘플 01번으로 표시하며 `legacyNumber: 13`으로 이전 번호도 유지합니다.
- 새 이미지는 `photos/sample-ID-UUID.jpg/png/webp`에 저장합니다. 기존 이미지 파일은 교체·삭제·타입 삭제 시 자동 삭제하지 않습니다.
- `.nojekyll`은 Pages 배포 설정입니다. `CODEX_PROMPT.md`는 기존 v2 요청 기록으로 유지합니다.

## 배포와 로컬 실행

GitHub Settings → Pages → Deploy from a branch → **main / (root)**로 배포합니다. 게시 후 Pages 작업이 완료되면 공개 사이트에 반영됩니다.

로컬에서는 HTTP 정적 서버로 폴더를 제공하세요. `file://` 또는 JSON 로딩 실패 상태에서는 내장 기본 미리보기를 표시하고 원격 게시를 차단합니다.

## PNG 저장과 호환성

- Canvas로 너비 1800px의 PNG를 만듭니다. 메모리 사용을 제한하기 위해 높이가 24000px를 넘으면 나눠 저장하도록 안내합니다.
- 생성 중 로딩 상태·중복 실행 방지, 이미지 로딩 타임아웃·오류 안내를 제공합니다. 자동 다운로드가 차단되면 **PNG 다운로드**를 누르세요. 선택 목록 안에도 다운로드 링크가 있습니다.
- 업로드한 이미지는 같은 출처의 `photos/`에서 제공됩니다. 외부 URL은 이미지 서버의 CORS 허용이 필요하며 허용하지 않으면 안내 후 중단합니다. CORS를 우회하거나 누락된 이미지로 선택표를 만들지 않습니다.
- 화면과 선택표 PNG에는 50% 워터마크를 적용합니다. 기존 사진 원본 파일은 수정하지 않습니다.
- PC Chromium과 모바일 터치 에뮬레이션에서 검수했습니다. iPhone Safari·Android 실기기 확인은 별도입니다.

## 검수

v3.1은 PC 1440×1080과 모바일 390×844 터치 에뮬레이션에서 타입 바로가기·키보드 접근, 13·24·25개 경계 페이지, 새 타일 편집·삭제·일괄 자동 확장, 선택 유지·오래된 저장값 정리, 긴 타입명 22개 레이아웃, PNG 저장을 검수합니다. 관리자 GitHub 게시 요청은 모킹으로 검사하며 실제 소스 배포·HTTP 응답은 별도로 확인합니다. 기존 403·충돌 방지·부분 실패 재시도·토큰 비저장 흐름도 유지합니다.

가격 설정이나 서버·분석 도구가 없으므로 임의의 예상 금액, 전체 방문자 선택 횟수·사용량 통계를 표시하지 않습니다. 상단 선택 개수는 현재 브라우저의 선택 상태입니다.
